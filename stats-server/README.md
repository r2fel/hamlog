# Служба обновлений и статистики

Маленькая служба, которая отвечает программе на вопрос «не вышла ли новая версия?»
и заодно считает, сколько копий программы в мире открывают и из каких стран.

**Что она знает о человеке:** случайный номер, который программа придумала себе при первом
запуске, версию программы, систему (mac/win), язык интерфейса и страну — страну определяет
Cloudflare по сетевому адресу, **сам адрес нигде не сохраняется**. Ни позывного, ни журнала,
ни одной связи. Кто выключил проверку обновлений в настройках — не попадает сюда вообще.

## Что где лежит

| Файл | Что делает |
|---|---|
| `app.mjs` | Вся логика: `/ping`, `/latest`, страница сводки |
| `page.mjs` | Сама страница со сводкой (в стиле программы) |
| `summary.mjs` | Как считаются цифры — одинаково и на ноутбуке, и в облаке |
| `store-d1.mjs` | Хранилище в базе Cloudflare D1 |
| `store-file.mjs` | То же хранилище, но в JSON-файле — для проверки на ноутбуке |
| `digest.mjs` | Письмо со сводкой раз в неделю |
| `worker.mjs` | Точка входа на Cloudflare |
| `local.mjs` | Точка входа на ноутбуке |
| `schema.sql` | Таблицы базы |
| `wrangler.toml` | Настройки Cloudflare |

## Проверить на своём компьютере (без всяких аккаунтов)

```bash
LATEST_VERSION=1.0.14 node stats-server/local.mjs
```

Служба поднимется на `http://127.0.0.1:4195`:

- сводка — `http://127.0.0.1:4195/s/test`
- письмо, как оно будет выглядеть, — `http://127.0.0.1:4195/digest`
- перекличка — `http://127.0.0.1:4195/ping?id=…&v=1.0.13&os=mac&lang=ru&cc=IT`
  (`cc` — подставить страну руками, на ноутбуке её взять неоткуда)

Чтобы сама программа ходила сюда, а не в интернет, запускать её так:

```bash
UPDATE_BASE=http://127.0.0.1:4195 PORT=4180 node server.js
```

Данные лежат в `stats-server/.data/stats.json` (в git не попадает).

## Перенести на Cloudflare

Нужен бесплатный аккаунт Cloudflare (карта не нужна).

```bash
npm install -g wrangler        # один раз
cd stats-server
wrangler login                 # откроется браузер, подтвердить вход

# 1. База
wrangler d1 create hamlog-stats
#    → в ответе будет database_id, вписать его в wrangler.toml
wrangler d1 execute hamlog-stats --remote --file=schema.sql

# 2. Секреты (спросит значение и не покажет его в файлах)
wrangler secret put STATS_SECRET   # длинная случайная строка — это адрес страницы сводки
wrangler secret put BREVO_KEY      # ключ почтового сервиса, если нужно письмо

# 3. Выложить
wrangler deploy
```

После `deploy` в ответе будет адрес вида `https://r2fel-hamlog-updates.<ваш>.workers.dev`.
Его нужно:

1. вписать в `server.js` в константу `UPDATE_BASE` (в программе);
2. вписать в `wrangler.toml` в `STATS_URL` (для письма) — как
   `https://…workers.dev/s/<тот самый STATS_SECRET>`;
3. заполнить `GITHUB_REPO` в `wrangler.toml` (например `r2fel/hamlog`) — тогда служба сама
   будет узнавать последнюю версию из релизов GitHub, и при выпуске новой ничего больше
   делать не надо.

Страница сводки открывается по адресу `https://…workers.dev/s/<STATS_SECRET>`.
Кто адреса не знает — видит пустую заглушку. Письмо приходит по понедельникам в 06:00 UTC
(строка `crons` в `wrangler.toml`).

## Почта для еженедельного письма

Cloudflare сам письма не шлёт, поэтому нужен любой почтовый сервис с бесплатным тарифом.
В `digest.mjs` — Brevo (300 писем в день бесплатно):

1. завести бесплатный аккаунт на brevo.com;
2. подтвердить отправителя `r2fel@mail.ru` (придёт письмо со ссылкой);
3. создать ключ API и положить его в `wrangler secret put BREVO_KEY`.

Без ключа письмо просто не отправляется, всё остальное работает.
